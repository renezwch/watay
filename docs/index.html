SECTION 02 // VERIFICATION PROTOCOL & RUNTIME PROOF PRE-EMIT CONTRACT EXECUTION

How You Know the Generated Code Actually Works

Traditional code generators emit static text templates and hope they compile. Watay treats code generation as a verified build pipeline: an SDK is only emitted after passing live HTTP contract assertions.

FLAG: --verify --heal
[01/04]

Ephemeral HTTP Roundtrip Before Emit

During generation, Watay boots a local HTTP contract server synthesized from your OpenAPI schemas and executes real network calls through every generated TypeScript and Python method—checking auth headers, path interpolation, query encoding, and status handling.

[02/04]

Standalone Test Suite Shipped in Every SDK

The exact contract tests used to verify the build are written into tests/contract.test.ts and tests/test_contract.py inside your SDK. Run them anytime with node --test or python3 -m unittest without installing third-party test runners.

[03/04]

Runtime Payload Guards in Production

Compile-time types vanish at runtime. Watay embeds a zero-dependency schema validator into every client so if a backend deployment accidentally drops a required field, the SDK throws a precise ValidationError($.data[0].amount) at the boundary.

[04/04]

Byte-Identical Determinism

No probabilistic LLM lottery in your build pipeline. Identical OpenAPI inputs produce byte-for-byte identical files across runs, yielding clean 5-line git diff pull requests whenever an endpoint changes.

SECTION 04 // COMPILER & RUNNER ARCHITECTURE SUBSYSTEM SPECIFICATIONS
SYS_01 // VARIANCE_ENGINE

Contravariant / Covariant Diffing

Evaluates request inputs contravariantly and response outputs covariantly. Tightening a request maximum or removing a response property triggers a major bump; widening a request union is marked safe.

SYS_02 // ZERO_DEPENDENCY_TARGETS

Zero Supply-Chain Footprint

Generated TypeScript SDKs rely strictly on standard fetch. Generated Python SDKs use standard dataclasses and urllib.request. No transitive dependency vulnerabilities in your consumers' trees.

SYS_03 // WIRE_NAME_HYGIENE

Reserved Keyword & Wire Mapping

Automatically sanitizes reserved language identifiers (such as from, class, or async in Python and TypeScript) into safe field names while preserving exact JSON wire serialization.

SYS_04 // RESILIENCE_PRIMITIVES

Idempotent Retries & Backoff

Every generated client includes configurable exponential backoff with jitter for idempotent HTTP methods on transient 429, 502, 503, and 504 responses, plus structured ApiError exceptions.

SYS_05 // SELF_HEALING_HOOK

Deterministic + BYOK Repair Loop

When --heal is enabled, Watay automatically resolves common schema edge cases and supports an optional Bring-Your-Own-Key repair callback inside your runner—gated strictly behind the contract verifier.

SYS_06 // AIR_GAPPED_SECURITY

Air-Gapped & Runner-Native

Executes inside standard GitHub Actions or self-hosted runners using the native GITHUB_TOKEN. No external webhook servers or source-code write tokens required.
